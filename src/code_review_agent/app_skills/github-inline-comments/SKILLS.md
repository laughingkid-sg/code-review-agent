# GitHub Inline Comments

Use this skill when preparing findings that may become GitHub PR review comments.

- Select one exact line per finding.
- Prefer the changed line that caused the issue over surrounding context.
- Avoid duplicate findings for the same rule within a few nearby lines.
- Include a concise recommendation and corrected code only when the fix is clear.
- Do not ask for broad rewrites in an inline comment when a smaller actionable fix is available.
- Keep the comment body useful without requiring the reader to inspect the provider transcript.
